# Fix Notification System — Admin Messages Visible to Mobile Users

## Problem

The mobile app's `showNotificationPanelDialog()` queries Firestore with:
```java
.whereEqualTo("uid", currentUser.getUid())
.whereEqualTo("isUserTargeted", true)
.orderBy("createdAt", Query.Direction.DESCENDING)
```

But there are **two issues** preventing admin messages from appearing:

1. **Missing Firestore Composite Index**: The query combines two equality filters (`uid` + `isUserTargeted`) with an `orderBy` on `createdAt`. This requires a composite index that doesn't exist (`firestore.indexes.json` is empty). The query silently fails on the mobile app.

2. **`createAdminNotification` Cloud Function ignores user targeting**: The `createAdminNotification` function (lines 135-155 in `functions/index.js`) creates notifications WITHOUT `uid` or `isUserTargeted` fields. So notifications created through this function won't match the mobile app's query filters.

Note: The complaint reply flow (AckButton + ReplyDialog) already correctly sets `isUserTargeted: true` and `uid`, so those DO work once the index exists.

## Changes

### 1. Add Firestore Composite Index

**File**: `/Users/bosethrathnayake/LNBTI SEM4/financial manager web/firestore.indexes.json`

Add composite index for `notifications` collection:
```json
{
  "indexes": [
    {
      "collectionGroup": "notifications",
      "queryScope": "COLLECTION",
      "fields": [
        { "fieldPath": "uid", "order": "ASCENDING" },
        { "fieldPath": "isUserTargeted", "order": "ASCENDING" },
        { "fieldPath": "createdAt", "order": "DESCENDING" }
      ]
    }
  ],
  "fieldOverrides": []
}
```

### 2. Fix `createAdminNotification` Cloud Function to Support User Targeting

**File**: `/Users/bosethrathnayake/LNBTI SEM4/financial manager web/functions/index.js`

Update the `createAdminNotification` function (line 135) to accept optional `uid` and `email` parameters, and set `isUserTargeted: true` when a `uid` is provided:

```javascript
exports.createAdminNotification = functions.https.onCall(async (data, context) => {
  // ... existing auth checks ...

  const { title, body, type = 'system', uid, email } = data;
  // ... existing validation ...

  const notification = {
    title,
    body,
    type,
    read: false,
    createdAt: admin.firestore.FieldValue.serverTimestamp(),
  };

  // If targeting a specific user, add the fields the mobile app queries on
  if (uid) {
    notification.uid = uid;
    notification.isUserTargeted = true;
  }
  if (email) {
    notification.email = email;
  }

  await db.collection('notifications').add(notification);
  return { success: true };
});
```

### 3. Update Firestore Rules to Allow Mobile Reads (already correct — no change needed)

The existing rules at lines 66-78 of `firestore.rules` already correctly enforce:
- `get`: admin OR (signed in + `isUserTargeted == true` + matching `uid`)
- `list`: admin OR (signed in + matching `uid` + `isUserTargeted == true`)

No changes needed here.
